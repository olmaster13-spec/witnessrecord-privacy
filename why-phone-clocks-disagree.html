Why phone clocks disagree, and what to do about it

How phones get the time, how far off it can be, and how to put several phones on one clock.

When you line up video from two phones, the file timestamps almost never agree. This page explains why, how big the gap can be, and the idea behind comparing two clocks over a short link. It is background for Witness Crew and for anyone syncing footage by hand. Written by the developer of Witness Camera, so read it with that in mind; where another approach is better, it says so.

Short answer. A phone sets its clock from a network time source, and the process can be off by an unknown amount because the request and the reply may travel for different lengths of time. Two phones can therefore disagree by a fraction of a second or more. You can measure the difference between two phones by sending a time back and forth and removing the round-trip delay; Witness Crew does this and stamps each recording with the result.

Where a phone gets the time

Most phones set their clock automatically from a network time source, sometimes the mobile carrier and sometimes an internet time server. Android's documentation says it uses the Simple Network Time Protocol, SNTP, over UDP, by default asking Google's public time servers, and that by default it does so about once a day. Android 14 and later can use more than one server. Between checks, the phone's own clock keeps time and can drift. I have not found Apple's published accuracy figures for iPhone, so I will not give one.

Why the answer can be wrong

SNTP assumes the request takes as long to reach the server as the reply takes to come back. If the two legs differ, the error grows. Android's documentation gives a theoretical worst case of about 2.5 seconds, when all the delay is on one leg. Mobile networks can add uneven delays like this. In normal conditions the error is usually far smaller, but it is not measured for you and not shown to you.

The result is that two phones on different carriers, or one set a day ago and one set a minute ago, can disagree by more than a video frame, which at 30 frames per second is a thirtieth of a second.

How to compare two clocks directly

Two phones near each other can compare clocks without a server, the same way network time works. This is the method Witness Crew uses:

  1. Phone A sends a message with the time it was sent.
  2. Phone B records when the message arrived and when it replied, and puts both in the reply.
  3. Phone A notes when the reply arrived. The round-trip time, minus the time B spent before replying, is the delay of the trip.
  4. B's clock is taken to have read its time at the middle of the trip, which gives an offset between the two clocks, with an error of at most half the delay.
  5. Repeat in a quick burst and keep the exchange with the shortest delay, because the shorter the trip, the less room there is for error.

In Witness Crew, each member other than the organizer sends a burst of twelve of these exchanges to each phone it meets (the organizer's clock is the reference and is never measured), discards any answer that took a second or more, and keeps the tightest result. Offsets chain back to the organizer, so two members who never met each other still share one timeline, with the uncertainty of each link added up. The Crew screen shows the resulting match in milliseconds, and each recording's manifest carries the offset and its uncertainty.

What this means in practice

  • For editing: a measured offset places a clip to within a frame or better when the uncertainty is small, without any audio matching. Audio sync is still a good check. See how to sync videos from multiple phones.
  • For logging: if you note the time by hand, remember it is the phone's time, which may be off.
  • For evidence: a matched clock tells you how two phones relate to each other. It does not prove what time it really was. For that, an independent time-stamp authority signs a hash of the recording's manifest, as in trusted time-stamping with RFC 3161.

Limits

  • The method needs the phones to be in contact once, nearby, before filming. Without that, Crew uses each phone's own time.
  • It corrects the difference between clocks at that moment. A phone's clock can drift afterwards, so match clocks shortly before filming, not days before.
  • The shortest-delay rule assumes the trip is about equally fast in both directions, which is the same assumption network time makes. A short trip limits how wrong that can be, but does not remove it.

Questions

Why do two phones show different times?

Each sets its clock from a network time source at different moments and the request and reply can take different times, so the result can be off by an unknown amount. Each clock can also drift between checks.

How far apart can phone clocks be?

Usually a fraction of a second, but there is no guarantee. Android's documentation gives a theoretical worst case of about 2.5 seconds for its network time method.

How can I sync two phones to the same clock?

Compare them directly by sending a time back and forth, removing the round-trip delay, and applying the difference. Witness Crew does this on iPhone when the Crew screen is open on both phones.

Does a matched clock prove when something happened?

No. It shows how two phones relate to each other. Independent time-stamping is what proves a recording existed by a certain time.
